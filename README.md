# 多语言目录整理台

按商品主键合并不同语言字段的目录整理工具：回退解析、同语言冲突待处理、市场规则校验、批量修改与市场文件导出。零运行时依赖、零构建步骤，原生 ES Module + 浏览器原生 API，直接静态托管即可。

## 运行

```bash
npm start            # 启动本地静态服务器，默认 http://localhost:8123
# 或任意静态服务器：python3 -m http.server 8123
npm test             # 纯逻辑单元测试（node:test，19 个用例）
npm run smoke        # 可选 DOM 冒烟（需先 npm i -D jsdom esbuild，37 项断言）
```

## 目录结构

```
src/
  languages.js   语种配置与回退链（与市场解耦）
  markets.js     市场配置：单位/长度/禁用词/类目映射，按市场独立
  sample-data.js 中英日样例（8 个商品，覆盖全部异常场景）
  catalog.js     合并、冲突检测、回退解析与来源标注（纯函数）
  validation.js  按市场规则校验：缺译/长度/禁用词/单位/类目映射
  batch.js       批量修改预演（商品数+字段差异）与不可变落盘
  export.js      市场文件导出（标明目录版本，剔除未裁定冲突）
  store.js       前端状态与 localStorage 持久化
  app.js         UI 渲染与交互
tests/           node:test 逻辑测试
scripts/         本地静态服务器与 DOM 冒烟脚本
```

## 核心规则

### 1. 按主键合并与冲突处理
- 以 `productId` 分组，再按 `language` 归并同语种多版本。
- 同一字段在同语种出现两个及以上**不同非空值**即判定冲突，进入「待处理」，字段在裁定前视为无可用值，系统**绝不随机挑选**。
- 在编辑抽屉中逐项选择版本（`v1/v2`）完成裁定；未裁定商品不参与批量修改，导出时被剔除并列入 `skipped`。

### 2. 回退与来源
- 回退链在 `languages.js` 配置（如 ja → en → zh），并按目标市场支持的语种裁剪。
- 回退**只填补空字段**，不覆盖本语种已有值。
- 人工锁定的译文（含人工清空）优先级最高，回退语言**不得写入**锁定字段，UI 与导出均标注来源：本语种原文 / 回退·来源语种 / 人工译文 / 冲突已裁定 / 人工锁定留空 / 缺失。

### 3. 市场与语种分离
- 市场只引用语种代码；单位允许列表、标题/描述长度上限、禁用词表、类目映射均按市场独立配置，切换市场后全部规则重新计算。
- 类目映射缺失时保留原始 code，提示「映射缺失」，不静默丢弃或猜测。

### 4. 筛选与批量修改
- 问题筛选（缺译、长度超限、禁用词、单位不允许、类目映射缺失、同语言冲突）之间为 **OR**，搜索与之 **AND**。
- 批量修改先**预演**：展示涉及商品数、逐条字段差异（from → to）、因冲突被排除的商品、因锁定被跳过的数量；确认后才落盘，且全部标记为人工锁定译文。
- 存在同语言冲突的商品在批量阶段自动排除，需先逐项裁定或不纳入操作范围。

### 5. 导出
- 导出文件仅含目标市场支持的语种，文件头标明 `catalogVersion`、市场规则（语种/单位/长度/禁用词）与生成时间，每个字段附 `sources` 与校验 `issues`，保证可追溯。
- 文件名：`catalog-<市场>-<目录版本>.json`。

## 样例覆盖的场景

| 商品 | 场景 |
| --- | --- |
| P001 | 完整中英日基准，无冲突 |
| P002 | 英语描述缺失 → 回退中文并标注来源 |
| P003 | 日语标题缺失（回退英语）；单位「缶」不在 JP 允许列表 |
| P004 | 英语 v1/v2 标题与描述冲突 → 待处理，禁止自动选值 |
| P005 | 中文描述超 CN 长度上限；标题含禁用词；类目 `wellness` 无映射 |
| P006 | 英语标题含 US/SG 禁用词 `best`；单位跨市场合法性差异 |
| P007 | 日语条目人工锁定留空 → 回退不得写入 |
| P008 | 日语描述超 JP 上限；英语标题含禁用词 `#1` |

人工修改保存在浏览器 localStorage，可通过顶部「重置人工修改」恢复原始目录。
